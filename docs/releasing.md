# Release & Changeset Workflow

This guide explains how Stellar Streams manages releases, changesets, and versioning. It covers when contributors should create changesets, what the release PR looks like, and how maintainers cut a release.

---

## Overview

Stellar Streams uses [**Changesets**](https://github.com/changesets/changesets) to manage versioning and changelog generation for all packages in the monorepo. This workflow:

1. **Contributors** add changesets when making changes that affect package versions
2. **Changesets bot** opens a Release PR when changesets are detected
3. **Maintainers** merge the Release PR to publish new versions to npm

The CHANGELOG.md is **automatically generated** from changesets during the release process.

---

## When to Create a Changeset

Create a changeset when your pull request **changes code that affects a published package**:

### ✅ Create a changeset for:

- **New features** in any `packages/*` workspace (`sdk`, `types`, `utils`, `hooks`, `contracts`, `wallets`, `ui`)
- **Bug fixes** in published packages
- **Breaking changes** in published packages
- **Documentation updates** in published packages (minor changes to README or JSDoc)

### ❌ Do NOT create a changeset for:

- Changes to the `apps/web` dashboard (not a published package)
- Changes to `contracts/` source code (Soroban contracts are deployed individually, not published to npm)
- Infrastructure changes (CI/CD workflows, Docker files, build scripts)
- Documentation-only changes to `docs/`, `.github/`, or root project files
- Chore commits (dependency updates managed by Dependabot already have bots that create changesets if needed)

## Creating a Changeset

### Step 1: Write Your Code

Make your changes in a feature branch and commit them with [Conventional Commits](../CONTRIBUTING.md#git-commit-conventions):

```bash
git checkout -b feat/add-new-hook
# Make your changes...
git add .
git commit -m "feat(hooks): add usePaymentStream hook"
```

### Step 2: Create the Changeset

Before pushing, run the changeset CLI:

```bash
pnpm changeset
```

This opens an interactive prompt:

```
🦋  Which packages would you like to include? (Use arrow keys)
❯ @stellar-starter-kit/sdk
  @stellar-starter-kit/types
  @stellar-starter-kit/utils
  @stellar-starter-kit/hooks
  @stellar-starter-kit/wallets
  @stellar-starter-kit/ui
```

1. **Select packages** affected by your PR using the arrow keys and spacebar. Toggle multiple if needed.
2. **Choose the bump type**:
   - `patch` – bug fixes, minor internal changes
   - `minor` – new features (backward compatible)
   - `major` – breaking changes
3. **Write a summary** describing what changed in user-facing terms (this appears in the CHANGELOG):

```
usePaymentStream hook for React applications

Provides real-time stream balance and vesting state updates. Includes
automatic refetch on transaction confirmation and support for both
streaming and vesting operations.
```

4. **Repeat for other packages** if your changes span multiple packages.

### Step 3: Commit and Push

The changeset creates a file in `.changeset/` with a human-readable name:

```bash
$ ls .changeset/
tiny-ropes-think.md
```

Commit this file along with your code:

```bash
git add .
git commit -m "feat(hooks): add usePaymentStream hook"
git push origin feat/add-new-hook
```

### Example Changeset File

`.changeset/tiny-ropes-think.md`:

```markdown
---
"@stellar-starter-kit/hooks": minor
---

usePaymentStream hook for React applications
```

## The Release PR

When one or more changesets are merged to `main`, the [**Changesets GitHub Action**](../.github/workflows/release.yml) automatically creates a **Release PR**:

```
[changeset] 🦋 Version Packages

This PR was generated by Changesets.

Releases:

- @stellar-starter-kit/sdk@0.2.0
- @stellar-starter-kit/hooks@0.1.1
- @stellar-starter-kit/types@0.2.0
```

### What the Release PR contains:

1. **Updated `package.json` files** – version bumps based on changeset types
2. **Updated `CHANGELOG.md`** – summarized from all changesets:

```markdown
## [0.2.0] - 2026-10-15

### Added

- `usePaymentStream` hook for React applications
- Support for streaming to multiple recipients

### Changed

- Internal refactor of payment state machine
```

3. **Removed `.changeset/*.md` files** – consumed during the version step

### Reviewing the Release PR

Maintainers should verify:

- ✅ Version bumps are correct (major/minor/patch)
- ✅ CHANGELOG.md entries are clear and user-focused
- ✅ All affected packages are included
- ✅ No unintended packages were versioned

## Cutting a Release (Maintainers)

### Prerequisites

- You have **write access** to the repository and npm registry credentials
- The **Release PR is open** and all CI checks pass
- You've **reviewed the changes** in the Release PR

### Step 1: Merge the Release PR

Approve and merge the Release PR to `main`. The automated release workflow will:

1. Run `pnpm install` to update lockfile
2. Run `pnpm run release-packages` (which calls `changeset publish`)
3. Publish changed packages to npm
4. Create git tags for each released package
5. Push tags back to the repository

Example tags created:

```
@stellar-starter-kit/sdk@0.2.0
@stellar-starter-kit/hooks@0.1.1
@stellar-starter-kit/types@0.2.0
```

### Step 2: Verify Published Artifacts

After the workflow completes, verify each published package on npm:

```bash
# Check the latest version
npm view @stellar-starter-kit/sdk versions

# Verify the package contents
npm pack @stellar-starter-kit/sdk@0.2.0
tar tzf stellar-starter-kit-sdk-0.2.0.tgz | head -20
```

Check [npm packages](https://www.npmjs.com/org/stellar-starter-kit):

- `@stellar-starter-kit/sdk`
- `@stellar-starter-kit/types`
- `@stellar-starter-kit/utils`
- `@stellar-starter-kit/hooks`
- `@stellar-starter-kit/wallets`
- `@stellar-starter-kit/ui`

### Step 3: Create a GitHub Release

Go to [Releases](https://github.com/SorobanForge/stellar-streams/releases) and create a GitHub Release matching the tag. Use the CHANGELOG.md entry as the release notes.

### Monitoring the Release Workflow

The release workflow is defined in [`.github/workflows/release.yml`](../.github/workflows/release.yml):

- Triggers on every push to `main`
- Checks for unpublished changesets
- If found, opens a Release PR
- If the Release PR is merged, publishes to npm and creates tags

View workflow runs: [Actions > Release](https://github.com/SorobanForge/stellar-streams/actions/workflows/release.yml)

## CHANGELOG.md Management

### Automatic Generation

The CHANGELOG.md is **automatically generated** during the release process:

- Each changeset becomes a section in the CHANGELOG
- Grouped by package and change type (Added, Changed, Fixed, etc.)
- Generated by the [@changesets/cli changelog](https://github.com/changesets/changesets/tree/main/packages/changelog-cli) package

### Manual Maintenance

The current CHANGELOG.md contains **pre-changeset releases** (0.1.0 and 0.2.0) that were written manually. These entries remain for historical reference.

**Going forward**, the CHANGELOG is generated automatically:

1. ✅ All new entries are generated from changesets
2. ✅ Manual edits to new sections are overwritten on the next release
3. ✅ The file is committed to git as part of the Release PR

### If You Need to Manually Update CHANGELOG.md

If you need to refine the CHANGELOG for the current release cycle (before the Release PR is merged), edit `.changeset/*.md` files instead of CHANGELOG.md directly. The CHANGELOG is regenerated when the Release PR is created.

For historical entries (pre-changeset releases), update CHANGELOG.md directly, but only above the current version line.

## Troubleshooting

### "No changesets found" – Release PR not opening

If your changes should trigger a release but the Release PR isn't opening:

1. Verify you **committed `.changeset/*.md`** files (check `git log --name-status`)
2. Check that the changeset file is **not in `.gitignore`**
3. Verify your branch is **merged to `main`**
4. Check the [Release workflow logs](https://github.com/SorobanForge/stellar-streams/actions/workflows/release.yml)

### "Version already published to npm"

If `changeset publish` fails saying a version is already on npm:

1. Check npm for the version: `npm view @stellar-starter-kit/sdk@0.2.0`
2. If it exists, the package was already released
3. Verify the `package.json` version was incremented correctly
4. Check for duplicate tags: `git tag | grep @stellar-starter-kit/sdk@`

### Manual Release (Emergency)

If the automated workflow fails and you need to release manually:

```bash
# Pull latest changes (including Release PR merge)
git pull origin main

# Install and build
pnpm install
pnpm build

# Publish packages (requires npm token)
pnpm run release-packages

# Create and push git tags manually
git tag @stellar-starter-kit/sdk@0.2.0
git push origin @stellar-starter-kit/sdk@0.2.0
```

## FAQ

**Q: Do I create a changeset for smart contracts (Rust)?**

A: No. Soroban contracts are deployed directly and versioned separately. Version them manually in `contracts/*/Cargo.toml` if needed, but do not create changesets.

**Q: What if I forgot to create a changeset?**

A: Create it before your PR is merged. If it's already merged, create a new changeset in a separate PR.

**Q: Can multiple people work on changesets for the same package?**

A: Yes. Each PR creates its own changeset file. When merged, multiple changesets for the same package are combined into one release section.

**Q: How do I mark a change as a breaking change?**

A: Use `major` bump type when creating the changeset. Include "BREAKING CHANGE:" in the summary:

```
BREAKING CHANGE: StreamsClient now requires signTransaction callback

Changed the client API to support wallets that batch sign operations.
```

**Q: How do I revert a release?**

A: Changesets do not support reversions. Publish a new patch release with fixes instead.
